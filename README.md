# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用，无需构建。

## 分层结构

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构与样式，仅按顺序引入下面三个脚本 |
| `js/rules.js` | 规则层（纯数据，不碰 DOM/localStorage）：工序流转、门禁判定、返工、缺陷记录的增改、旧数据规整 |
| `js/storage.js` | 存储层：localStorage 读写、首次种子数据、加载时逐条执行旧数据迁移 |
| `js/app.js` | 页面层：新增表单、看板、详情弹窗、筛选排序、JSON 导出；所有变更先过规则层，再由存储层持久化 |

## 工序流转规则

工序固定为 **贴线中 → 待阴干 → 上金粉 → 待交付**，只能逐道推进，不能跳序：

- 「贴线中 → 待阴干」：随时可推进。
- 「待阴干 → 上金粉」：必须**阴干日期已到（含今天）**，且作品**没有状态为「待修复」的缺陷**；任一条件不满足，推进按钮禁用并在悬停/详情中显示原因。
- 「上金粉 → 待交付」：推进时贴线进度自动记为 100%；进入上金粉时金粉状态自动记为「已上金粉」。
- 返工只能退回**紧邻的上一道**，且**必须填写返工原因**，原因写入流转记录；贴线中不可再退。

## 缺陷记录

- 缺陷从一段文字升级为结构化记录：`id / text / status(待修复|已修复) / createdAt / fixedAt / fixNote / migrated`。
- 旧数据里的 `defect` 文本在存储层加载时**自动迁移为一条「待修复」记录**（带 migrated 标记并写日志），迁移幂等，不会重复生成。
- 标记修复时记录变为「已修复」并保留修复时间与说明，**记录不删除，历史可查**；详情弹窗中列出完整流转记录。
- 新作品统一从「贴线中」起步、金粉「未处理」；表单中的初始缺陷会直接记为待修复。

## 功能清单

- 新增作品（胎体、纹样、线条、贴线进度、阴干日期、交付日期、初始缺陷、备注）。
- 四列工序看板，卡片显示进度、阴干/交付日期、金粉状态与「n 处待修复，m 处已修复」摘要；按钮按规则启用/禁用。
- 今日与风险：已到期待阴干、待修复缺陷、最近交付三个摘要列表。
- 详情弹窗：门禁原因提示、推进、返工（填原因）、记录/修复缺陷、完整流转记录。
- 主题筛选、状态筛选、按交付/阴干日期排序、清空筛选。
- localStorage 持久化与 JSON 导出（导出含完整缺陷历史与日志）。
